# External review — Gemini (2026-07-25)

> Reviewer evaluated architecture/logic from description + code; no test run.

This is a well-conceived portfolio piece: focusing on state-table exhaustion over brute-force bandwidth shows a mature understanding of modern network resilience. However, the recent fixes introduce critical regressions, particularly around metric validity and failure classification.

## 1. Critical: False "Healthy" Verdict on Service Crash (Fix 3 Audit)

File/Domain: classify.rs / engine probe (Health Probe)

Concrete Failure: You mapped ECONNREFUSED to "target up & refusing". This is fundamentally flawed for an application-layer stress test. If your load successfully crashes the target's web server (e.g., NGINX OOMs and dies) but the target OS remains online, the OS network stack immediately replies to the health probe's SYN with a RST (ECONNREFUSED). Your classifier declares the target "Healthy" or "MitigationEngaged" when you have actually achieved a total denial of service.

Severity: Critical — massive false negative, completely missing a successful attack.

Smallest Correct Fix: Split the health probe into NetworkHealth (ICMP/L3) and ServiceHealth (TCP port). ECONNREFUSED on the service port must result in a Down (Service Offline) verdict. Only ECONNREFUSED on an expected closed port indicates OS survival.

## 2. High: The RPS Metric is Now Useless for State-Exhaustion (Fix 1 Audit)

File/Domain: engine/mod.rs / metrics.rs

Concrete Failure: By calculating RPS exclusively from responses_ok, you broke telemetry for state-exhaustion vectors. Vectors like slowloris, rudy, and tcp_exhaust intentionally never complete requests. Under the new logic, a highly successful Slowloris run reports 0 RPS and 0 error_rate (if connections are simply held). The classifier and adaptive governor fly blind because they see no "completed" traffic.

Severity: High — blinds the engine to its own primary attack methodology.

Smallest Correct Fix: Track two distinct metrics: Load_RPS (based on requests_sent / connections established) and Goodput_RPS (based on responses_ok). Use Goodput for L7 flood evaluation, but use Load (connection concurrency) for L4/Slow vector evaluation.

## 3. High: Immediate EMFILE Crash via Hardcoded Concurrency

File/Domain: presets.rs / engine/mod.rs

Concrete Failure: You hardcoded PRESET_CONCURRENCY = 2700. The default fd limit (ulimit -n) on macOS and many Linux distros is 1024 or 2048. The moment a user fires a preset, the engine attempts to spawn 2700 sockets, instantly hits EMFILE/ENFILE, and collapses.

Severity: High — the tool fails to run out-of-the-box on standard developer machines.

Smallest Correct Fix: On startup, read RLIMIT_NOFILE. If it is less than PRESET_CONCURRENCY + 100, either automatically scale down and warn, or fatally exit with instructions to run `ulimit -n 65535`.

## 4. Medium: Thundering Herd via Flat Throttling (Fix 2 Audit)

File/Domain: engine worker

Concrete Failure: A flat 50ms backoff on Err synchronizes asynchronous workers. If an intermediate firewall resets 2,000 connections simultaneously, all 2,000 Tokio workers sleep for exactly 50ms, then wake and call connect() at the same microsecond — extreme, unnatural spikes in local CPU and network queuing.

Severity: Medium — artificial latency spikes that corrupt the collapse curve.

Smallest Correct Fix: Add jitter. Sleep random(25..75) ms instead of flat 50ms. For sustained Err loops, implement capped exponential backoff.

## 5. Medium: Histogram Snapshot Tearing (Rust Quality)

File/Domain: engine/histogram.rs / sampler

Concrete Failure: If the 512-bucket histogram uses an array of atomic counters, the sampler reading buckets sequentially every 250ms races the workers updating them. The sampler might read buckets 0-100 before a batch of latency spikes and 101-511 after — a "torn snapshot" producing wildly inaccurate p95/p99 for that window.

Severity: Medium — limits mathematical integrity of the primary verdict mechanism.

Smallest Correct Fix: Double-buffering. Maintain two atomic histogram arrays; every 250ms the sampler uses AtomicPtr::swap to flip the active histogram, reads the inactive one at its own pace, resets it to zero, waits for the next tick.

> NOTE (from the author's own audit): the current histogram is a single snapshot-delta
> array, not double-buffered; whether per-window tearing is material is worth
> measuring. This finding is plausible but unverified against the actual histogram.rs.

## 6. Low: Consent Gate Bypass via Pseudo-Terminals (Safety)

File/Domain: auth.rs / main.rs

Concrete Failure: You rely on TTY checks + dialoguer for human-in-the-loop consent. An adversarial operator can bypass this using PTY automation (expect script: `expect "I HAVE AUTHORIZATION"; send "I HAVE AUTHORIZATION\r"`).

Severity: Low — as a local CLI tool, preventing the host's owner from automating input is ultimately impossible.

Smallest Correct Fix: You cannot fully prevent this in a standalone binary. Acknowledge the limitation in the threat model. To raise the bar slightly, include a randomized challenge string (e.g., `Type "I HAVE AUTHORIZATION - 8F2A"`).

## Design & Résumé Value

The state-table exhaustion framing is highly convincing and sets you apart from unoptimized bandwidth cannons.

The single change that would most raise credibility: Add PCAP / TCP-state validation output. A true security engineer doesn't just want the tool's final Verdict; they want the receipts. If the tool detects mitigation or degradation, dump the last 50ms of anomalous packet headers or a timeline of TCP state transitions (e.g., "At T+45s, target began returning RST for 98% of SYNs"). Proving *why* the tool reached its verdict elevates it from a black-box load generator to a forensic diagnostic instrument.
